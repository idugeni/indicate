# Stage 4 media and publication durability hardening

The change closes most of the original production/fake divergences by binding SHA-256 uploads end to end, persisting immutable target outcomes, guarding publication transitions in PostgreSQL, fencing worker writes by database time, and adding claimed reconciliation work. Thirteen of the sixteen original findings are fully addressed; transition receipt recovery, Article public eligibility, and archive invalidation remain incomplete, and the production lease-release path introduces a separate retry-timing regression. The complete Stage 4 gate passes, but its in-memory coverage does not exercise these production-only branches. **Watch for:** **high, confirmed** target retry backoff is overwritten during production lease release; **high, confirmed** cyclic target progress can make an old unacknowledged receipt permanently unreconcilable; **high, confirmed** archive invalidation misses Articles that reference media through `lead_media_id`; **medium, confirmed** draft Articles are treated as active for public media; **medium, confirmed** the live PostgreSQL suite does not cover these production branches.

**Verdict**: NEEDS_CHANGES

## High-level view

The upload contract now carries one base64 SHA-256 value from browser hashing through the storage port, signed R2 headers, HEAD metadata, and completion. The mandatory provider gate verifies the actual SDK signature and a credential-free exact-object behavior contract, while optional live tests retain the managed-service round trip.

Publication history now lives on immutable job targets, and database triggers define both normal transitions and the deliberate terminal-to-queued Article Site republish projection. Dispatch exhaustion produces terminal targets and a readable result. **High, confirmed:** the production worker replaces a target retry’s durable future dispatch time with the current time when releasing the lease, bypassing the configured delay schedule.

Fenced writes and releases now require a database-time unexpired lease, expired recovery respects `maxAttempts`, and one invocation-wide budget caps processed targets. Dispatch, receipt, and cleanup reconciliation use claims or guarded compare-and-set mutations, and cleanup reaches a terminal failure. **High, confirmed:** receipt reconciliation infers whether an old transition committed from the target’s current state, so cyclic retry progress can return to the receipt’s `fromState` and poison reconciliation.

Public media authorization now checks an Article record, archive errors distinguish unavailable rows from verified stale versions, and authenticated denials append sanitized tenant-local audits. **Medium, confirmed:** production maps both `draft` and `active` Articles to the domain’s `active` flag. **High, confirmed:** archive invalidation follows the media owner rather than every Article `lead_media_id` reference.

The local gate passed configuration, typecheck, lint and policies, 46 unit tests, 24 property tests, 40 integration tests, the secure production build, and 15 Playwright tests; `git diff --check` also passed. The separately reported fresh PostgreSQL 17 run passed 15 Stage 2 and 5 Stage 4 live tests. **Medium, confirmed:** the five Stage 4 cases do not cover production archive/public-media behavior, receipt cycling, cleanup claims, or retry timing at release.

## Production lease release bypasses target retry delays

**High, confirmed.** `transitionTarget` derives `publishing_jobs.next_dispatch_at` from the earliest retrying target (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:369-372`). `releaseJob` then sets that field to `now` whenever the job is `retrying` (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:394-398`). A normal retryable publication failure therefore returns to Redis immediately instead of waiting for the configured delay; repeated work invocations can hot-loop until the target’s own `next_attempt_at` becomes due. The in-memory repository preserves the future time, so the partial-retry tests do not expose the production regression. Release should choose `now` only when queued work remains because of the invocation budget, and otherwise preserve or recompute the earliest retry target time; add a live repository/worker assertion that Redis is scheduled at that future timestamp.

## Receipt recovery cannot distinguish a completed cycle from a missing transition

**High, confirmed.** Target transitions create unacknowledged receipts atomically and the worker acknowledges them after commit. Claimed reconciliation rejects a receipt whenever the target’s current state has returned to the receipt’s `fromState` (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:437-444`). For an unacknowledged `processing -> retrying` receipt, a later `retrying -> processing` transition makes the current state `processing`; reconciliation throws `invalid_transition`, aborts the receipt loop, and retries the same poisoned row after claim expiry. The in-memory reconciler requires exact equality with `toState`, so it also cannot handle subsequent progress.

The receipt row is written in the same transaction as the state mutation and audit, so reconciliation needs an immutable transition identity or version rather than current-state inference. The crash regression test reconciles before any later transition and never uses the existing acknowledgement-failure injection (`tests/integration/stage4-media-publication.integration.test.ts:153-168`). Exercise acknowledgement failure through `PublicationWorker`, allow lease recovery and a subsequent target transition, then prove the old receipt is acknowledged without blocking the batch.

## Archive invalidation does not traverse Article media references

**High, confirmed.** Articles can reference media through `articles.lead_media_id` (`src/infrastructure/db/schema/editorial.ts:105-114`), independently of the media row’s owner fields. Archive collects all Site Settings references, but its published-Article query runs only when `media.article_id` is non-null and follows that owning Article (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:182-184`). An Organization-owned asset—or media referenced by a different Article through `lead_media_id`—can therefore be archived without invalidating Sites where that Article is published.

Archive should select every same-tenant Article whose media reference equals the archived media ID, then union their published Article Site rows with Site Settings references before the deduplicated transactional inserts. The regression fixture uses an Article-owned asset and a relation for that same owner (`tests/integration/stage4-media-publication.integration.test.ts:90-105`), confirming Set-based deduplication but not reference traversal.

## Draft Articles remain public-media eligible

**Medium, confirmed.** Public authorization supplies Article lifecycle data to `canPublicAccessMedia`, which rejects an inactive Article. The production adapter defines that flag as `row.status !== 'archived'` (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:214-217`), so a `draft` Article with a stale published Article Site relation still authorizes its media. Public content selection requires `status === 'active'`; media authorization should use the same predicate and add a production-path draft-Article case.

## Resolution map for the original sixteen findings

The checksum contract in finding 1 is resolved: the CMS computes SHA-256 and sends every returned signed header, `ObjectStoragePort.authorizeExactPut` requires the checksum, R2 signs `ChecksumSHA256`, and completion compares only provider SHA-256 metadata. The provider contract covers signature headers, exact PUT/HEAD/GET/delete, checksum mismatch semantics, and anonymous denial (`app/cms/cms-workspace.tsx:186-194`, `src/infrastructure/storage/r2-object-storage.ts:44-70`, `tests/integration/stage4-provider-live.integration.test.ts:12-48`).

Findings 2 through 4 are resolved. Job targets persist `published_url` and `published_at`, status reads them rather than mutable Article Site values, and republish tests preserve job A after job B. The `stage4_article_site_transition_guard` permits terminal-to-queued only after a new queued durable target exists, while preserving exactly five publication states. Dispatch exhaustion transitions each target through a database-valid path to `failed`, records `dispatch_exhausted`, and projects a readable result (`drizzle/0006_stage4_media_publication_runtime.sql:14-21,86-120`; `tests/integration/stage4-postgres-live.integration.test.ts:102-142`).

Findings 5 through 7 are resolved at their original scope. Production target fetch, mutation, and release predicates use `clock_timestamp()` against the lease; expired recovery fails attempts at `maxAttempts`; and `PublicationWorker.run` decrements one `remainingBudget` across all claimed jobs. The stale-before-reconciliation, exhausted-recovery, and two-invocation budget regressions cover those behaviors (`src/application/stage4/publication-worker.ts:45-84`; `src/infrastructure/db/repositories/drizzle-stage4-repository.ts:331-421`). **High, confirmed:** the separate release-time retry regression described above still blocks shipping.

Finding 8 is only partially resolved. Receipt creation, acknowledgement, bounded claimed scans, and reconciliation now exist. **High, confirmed:** current-state validation cannot survive cyclic progress after an acknowledgement crash. Finding 9 is implemented with `FOR UPDATE SKIP LOCKED` claim functions plus token/expiry predicates for dispatch, receipts, and cleanup; expired lease recovery uses a fenced conditional update. Finding 10 is resolved because cleanup failure uses the shared retry policy and persists `failed` after exhaustion (`drizzle/0006_stage4_media_publication_runtime.sql:122-230`; `src/application/stage4/publication-worker.ts:95-128`).

**Medium, confirmed:** finding 11 is only partially resolved because archived Articles are denied but draft Articles are mapped as active. **High, confirmed:** finding 12 is only partially resolved because archive atomically unions and deduplicates Site Settings plus owner-Article Sites but misses Articles that reference the media through `lead_media_id`. Findings 13 and 14 are resolved: archive returns a non-disclosing denial for missing, foreign, or inactive rows, returns conflict only after locking a same-tenant active row with a stale version, and service denials append requesting-tenant audit records with `target_id = null` and a sanitized reason (`src/application/stage4/media-service.ts:31-39,122-132`; `src/infrastructure/db/repositories/drizzle-stage4-repository.ts:173-186`).

Finding 15 is resolved as a gate design: CI runs mandatory credential-free contracts, the R2 signature test uses the production SDK, the behavioral object contract verifies exact/private operations, and optional R2/Upstash suites remain available with secrets (`.github/workflows/stage2-quality-gate.yml:18-31`; `tests/integration/stage4-provider-live.integration.test.ts:12-79`). Finding 16 is resolved: the named owner-prefix and checksum checks exist in both Drizzle and migration 0006, and unit plus migration policy checks enforce parity (`src/infrastructure/db/schema/editorial.ts:243-257`; `scripts/check-migration-policy.mjs:25-48`).

## Production evidence still stops short of the repaired branches

**Medium, confirmed.** The fresh PostgreSQL validation proves all migrations and five Stage 4 repository cases, including immutable outcomes, transition guards, lease fencing, and dispatch exhaustion. `tests/integration/stage4-postgres-live.integration.test.ts` does not exercise production archive invalidation/denial auditing, public Article media status, transition receipt claims/reconciliation, cleanup claim exhaustion, overlapping claimers, or release-time retry scheduling. Those behaviors are covered only by the in-memory repository, which differs in retry release and receipt validation. Add live cases for the four remaining correctness paths and concurrent claim ownership so the production contract gates them.
