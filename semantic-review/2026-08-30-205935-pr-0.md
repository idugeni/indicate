# Shared public delivery, exact-domain activation, and cache invalidation for Stage 5

The change adds strict Host normalization, exact Site resolution, the shared news template, SEO/feed serializers, provider adapters, domain activation, and invalidation infrastructure. The approved architecture is recognizable, but **[critical, confirmed]** forced RLS prevents production hostname/content discovery, **[high, confirmed]** external workflows are not recoverable, and **[high, confirmed]** cache safety is disconnected from serving. Checkpoint 12 cannot safely proceed.

Watch for: **[critical, confirmed]** production public hosts cannot resolve through the runtime database role; **[critical, confirmed]** invalidation claims cannot be safely completed or fenced; **[high, confirmed]** domain activation/deactivation can acknowledge incomplete provider state; **[high, confirmed]** cache and mutation invalidation are not wired into production reads and writes.

**Verdict**: NEEDS_CHANGES

## High-level view

**[critical/high, confirmed]** The parser is strict and control-plane matching precedes exact Site lookup, but production queries forced-RLS tables before establishing Organization context. Middleware also rewrites local authorities to the CMS host in production, and the pending-domain endpoint succeeds without validating Host or pending state.

**[high, confirmed]** Exact Vercel operations are used instead of wildcard registration, but activation does not resume from persisted phases or schedule bounded retries, and failed deactivation cleanup is lost. Vercel verification can accept `verified: false`; Cloudflare checks assigned rather than publicly delegated nameservers and sends exact URL purges to unrelated zones.

**[medium/high, confirmed]** The principal reader surfaces render with React/XML/JSON escaping, but inactive Regions and verified affiliation scopes are not enforced. Site errors are unbranded, while absolute asset metadata, Site structured data, and favicon output remain incomplete.

**[critical/high, confirmed]** Cache identity, bypass schema, and invalidation plans exist only as disconnected pieces. Public reads never consult identity/bypass state, public mutations do not create complete plans, and task acknowledgement lacks both RLS context and claim fencing. Fixture-backed tests pass, but optional live checks do not execute these production boundaries.

8. **[High · confirmed] Public DNS delegation is not verified** — Cloudflare-assigned nameservers are compared to config, but registrar/public NS delegation is never checked. Add a public delegation check.
9. **[High · confirmed] Exact URL purge crosses zones** — Every URL list is sent to all configured zones. Partition purges by the owning zone only.
10. **[Critical · confirmed] Unfenced invalidation acknowledgement** — Completion/failure has no tenant context or claim token, so RLS blocks updates and stale workers are not fenced. Acknowledge through Organization- and token-scoped predicates/functions.

<details><summary>Details</summary>

## Forced RLS blocks public discovery

**[critical, confirmed]** `findActiveSitesByExactHostname` and `loadPublicSite` select directly without transaction-local Organization context (`src/infrastructure/db/repositories/drizzle-stage5-repository.ts:23-53`). The pooled `indicate_runtime` role is subject to forced policies keyed by `current_organization_id()` for Sites and all content relations (`drizzle/0001_stage2_security.sql:161-180`), so discovery returns no Site and content loading returns no rows. Use a narrowly scoped security-definer exact-host lookup, then establish the returned tenant context before content reads; exercise both as the runtime role.

**[medium, confirmed]** discovery joins active Domains but not Regions (`src/infrastructure/db/repositories/drizzle-stage5-repository.ts:23-26`). Deactivating a Region therefore leaves its Site and regional articles public. Require active same-Organization Region eligibility.

## Host classification has two bypasses

**[high, confirmed]** middleware rewrites `Host: localhost` and `Host: 127.0.0.1` to the CMS host without a development/test guard (`proxy.ts:8-12`). Production must reject those authorities rather than grant control-plane routing.

**[high, confirmed]** `/domain-pending` unconditionally returns 425/noindex (`app/domain-pending/route.ts:1`). It neither classifies Host nor proves an exact pending Site/attempt, so unknown and control-plane hosts can produce a successful probe. Bind the response to persisted pending state and bounded proof.

## Domain lifecycle is not recoverable

**[high, confirmed]** `resume` simply calls `activate` from the beginning (`src/application/stage5/domain-provisioning-service.ts:34-35`). Failures are not stored with bounded retry timing, repeated external creates are not phase-idempotent, and `previousHostname` is always null, excluding safe reconfiguration. No CMS/cron adapter invokes this service; production composition wires only resolver/content (`app/stage5-composition.ts:17-19`). Implement conditional phase continuation, old/new hostname state, reconciliation, and secured entry points.

**[high, confirmed]** deactivation commits database state before Vercel removal with no durable cleanup phase (`src/application/stage5/domain-provisioning-service.ts:38-40`). A Vercel failure leaves an orphan association that the same method cannot retry because the Site is already inactive.

**[high, confirmed]** Vercel verification accepts `body.name === hostname` independently of `body.verified` (`src/infrastructure/vercel/exact-domain-adapter.ts:13`). A matching unverified response is treated as success; require explicit verification.

**[high, confirmed]** Cloudflare authority compares expected values with the zone's assigned nameservers, not public NS delegation (`src/infrastructure/cloudflare/cloudflare-authority.ts:10`). Its exact URL purge also loops across every zone ID (`src/infrastructure/cloudflare/cloudflare-authority.ts:14`). Verify registrar-visible delegation and partition URLs by owning zone.

## Invalidation cannot be acknowledged safely

**[critical, confirmed]** the claim function creates a token, but the model drops it and completion/failure updates only by task ID without tenant context (`src/infrastructure/db/repositories/drizzle-stage5-repository.ts:93-96`). Forced RLS makes those runtime updates affect zero rows; without token/lease predicates, a stale claimant could overwrite a newer one after repair. Return and require Organization, processing state, and current claim token on acknowledgement.

**[high, confirmed]** no production cron/route runs `InvalidationDispatcher`, and its catch path calls Redis bypass before recording database failure (`src/application/stage5/invalidation.ts:23-44`). A coordination outage can leave the claim leased with no scheduled retry. Record durable retry progress independently of each external side effect.

## Cache safety is implemented only as helpers

**[high, confirmed]** `createCacheIdentity` and `cacheEntryMatches` are test-only; production exposes no cache reader and public routes are `force-dynamic` (`app/stage5-composition.ts:17-19`, `app/page.tsx:10`, `app/articles/page.tsx:4`). Robots/sitemap/RSS still emit CDN `s-maxage=300` without application context validation. Wire canonical identity and current-context checks into the actual cached read path.

**[high, confirmed]** migration 0007 creates `cache_bypasses`, but production never reads or writes it; only a Redis key with a 24-hour TTL is used (`src/infrastructure/redis/upstash-cache-coordination.ts:10`). Persist bypass state and consult it until reconciliation succeeds.

## Public mutations do not feed complete invalidation

**[high, confirmed]** Stage 3 settings, Article, Publisher, and Affiliation persistence inserts no invalidation tasks (`src/infrastructure/db/repositories/drizzle-stage3-repository.ts:147,189-193`). Stage 4 media tasks have tags but empty URL/path coverage (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:160,189`), and publication transitions do not produce Stage 5 plans. Create complete affected-Site tasks in the same transaction as each public mutation.

## Public trust and presentation are incomplete

**[high, confirmed]** the affiliation join requires only `active=true`, then exposes the institution whenever the Publisher is verified (`src/infrastructure/db/repositories/drizzle-stage5-repository.ts:45-53`). It ignores affiliation `verified_at` and `claim_scopes`, bypassing the existing verified-claim policy.

**[medium, confirmed]** repository media URLs are relative and flow directly into OG/JSON-LD image/logo values (`src/infrastructure/db/repositories/drizzle-stage5-repository.ts:52-53`, `src/application/stage5/seo.ts:33-39`). Listing pages omit generated WebSite/Organization JSON-LD, and `faviconUrl` is never emitted (`app/public-template.tsx:9-10`, `app/public-runtime.ts:19`). Convert assets through Hostname Context and render all required Site metadata.

**[medium, confirmed]** all non-Site classifications, including modeled ambiguous status 500, collapse to `notFound()` (`app/public-runtime.ts:10-13`, `app/page.tsx:14`). Resolved-Site failures use the generic shell in `app/error.tsx:2`. Preserve the non-indexable configuration error and Site-branded sanitized error behavior.

## Checkpoint tests do not cover production behavior

**[high, confirmed]** the live PostgreSQL test checks only schema objects (`tests/integration/stage5-postgres-live.integration.test.ts:8`), while the optional Vercel test checks project health only (`tests/integration/stage5-provider-live.integration.test.ts:7-9`). The four fixture-backed E2E cases omit malformed/reserved/ambiguous/deactivated hosts, cross-Site media, error branding, cache hit validation/invalidation, provider recovery, and live RLS (`tests/e2e/stage5-public-host-critical-flow.spec.ts:4-7`).

Local typecheck, lint/policies, build, 50 unit tests, 30 property tests, 43 non-live integration tests, and four Stage 5 E2E tests passed. Twenty-nine integration tests were skipped, including every Stage 5 live PostgreSQL/provider case. Task metadata records only optional properties 11.8–11.13 (`.kiro/specs/indicate-mvp/tasks.meta.json:96-122`); tasks 11.1–11.7, 11.14–11.16, and checkpoint 12 lack completion evidence.
