# Stage 3 tenant CMS, editorial, analytics, and audit services

Major Stage 3 adds tenant-aware CMS services for configuration, RBAC, Publisher verification, canonical Articles, Site assignment, public-content selection, analytics, and immutable auditing. The latest remediation fixes the previously reported permission coupling, destructive Site Settings updates, invalid-input mapping, Publisher metadata overexposure, revocable affiliations, and three broken property inputs. The production adapter still diverges from the in-memory behavior at the User RLS boundary and in Official Affiliation persistence, while analytics and public eligibility do not implement the approved semantics. **Watch for:** **Critical, confirmed** User RLS makes production Membership loading and User denial attribution invisible; **High, confirmed** affiliation owner changes are acknowledged but not persisted; **High, confirmed** job analytics are inferred from current assignments rather than job targets; **High, confirmed** pending Sites are public-eligible.

**Review decision**: CHANGES_REQUESTED

**Verdict**: NEEDS_CHANGES

## High-level view

Although Stage 3 applies `organization_id` throughout tenant-table reads, writes, joins, and version predicates, **Critical, confirmed:** its transaction context does not set the Auth identity required by the `users` RLS policy. The runtime role consequently cannot load Membership display data or attribute denied User actions.

Mutation and success-audit persistence share one PostgreSQL transaction, denial responses use one 404 envelope, and boundary schemas are strict. **High, confirmed:** Official Affiliation updates return and audit publisher/Site reassignment, but the production upsert omits both columns.

Publisher identity changes revoke verification, affiliations can be deactivated, and Article content remains canonical. **High, confirmed:** public selection checks Site lifecycle status but not activation state, allowing pending or failed hostname mappings to qualify.

Analytics is Organization-scoped, but **High, confirmed:** job Site/Region dimensions come from every current active assignment for the Article rather than the immutable targets of each job; outcome date filtering also uses assignment creation time.

**High, confirmed:** the green generated suite does not exercise several invariants named by Properties 9 and 11–13/34, while the production PostgreSQL contracts that expose runtime-only behavior were skipped locally.

<details><summary>Details</summary>

## Production Membership and denial auditing conflict with User RLS

The migration forces `users` through `auth_user_id = indicate_private.current_auth_user_id()` (`drizzle/0001_stage2_security.sql:205-209`). Stage 3 read, mutation, and denial transactions set only Organization, actor ID, and request ID through `set_tenant_context` (`drizzle-stage3-repository.ts:75-101`); that function does not set `app.auth_user_id`. The tenant snapshot then inner-joins Memberships to `users` (`drizzle-stage3-repository.ts:44`), and denial attribution queries `users` by actor ID (`:87-88`).

**Critical, confirmed:** with the forced-RLS runtime role, Memberships appear absent and User denial attribution evaluates false. `saveMembership` can attempt a duplicate insert instead of updating an existing Membership, while context/resource denials return without the required security Audit Log. Pass verified Auth identity into the transaction context or introduce a narrowly scoped, tenant-safe User projection/definer function; add a runtime-role contract that lists and updates an existing Membership and observes a denied User audit.

## Official Affiliation updates report a relation PostgreSQL keeps unchanged

`updateAffiliation` accepts a new `publisherId` and `siteId`, writes both into the returned record, and audits them (`tenant-business-service.ts:335-338`). The production insert includes those fields, but its conflict update changes only institution name, scopes, evidence, active state, verification time, version, and timestamp (`drizzle-stage3-repository.ts:148`).

**High, confirmed:** a caller can receive success and an immutable audit claiming reassignment while a reload still points to the old Publisher and Site. Either make publisher/Site immutable in the update DTO or persist both; verify the round trip through `DrizzleStage3Repository`.

## Job and outcome analytics do not represent historical targets

`buildAnalytics` joins each Publishing Job to all currently active Article Site assignments sharing the Article (`policies.ts:100-102`), although the schema has immutable `publishing_job_targets`. Assignment changes can therefore move, multiply, or erase a job's dimensions. The service filters Article Site outcomes by `createdAt` (`tenant-business-service.ts:484-487`), excluding a target created before a date range but published or failed during it.

**High, confirmed:** required Site/Region/state aggregates are tenant-scoped but historically incorrect. Load immutable job targets and define the date dimension from the publication transition/outcome timestamp. Property 9 should compare every projection with a generated multi-tenant, multi-Site, multi-date reference model.

## Public content accepts Sites that are not activated

`selectPublicArticles` treats `status === 'active'` as sufficient (`policies.ts:44`) and never evaluates `activationState`, even though Stage 3 changes an active Site to `pending` until Stage 5 activation completes (`tenant-business-service.ts:207-210`). The standard Stage 3 fixture uses an active/pending Site.

**High, confirmed:** direct public-content selection can expose content for a Site whose exact hostname is not activated. Require active lifecycle and activation state, or require a verified `HostnameContext` that makes the condition unrepresentable. Add pending and failed cases to Property 13.

## Membership commands contain a non-persisted display field

The Membership command accepts `displayName` (`schemas.ts:30`) and a create response/audit takes it from caller input (`tenant-business-service.ts:247-251`), but Membership persistence stores only User ID, Role, status, and version (`drizzle-stage3-repository.ts:139-143`).

**Medium, confirmed:** a newly added Membership can return and audit an arbitrary display name that is not the persisted record. Remove `displayName` from the mutation DTO and derive the response from the User projection, or add an Organization-local label column.

## Green tests do not establish the named Stage 3 properties

All 11 property files now execute and pass at 100 runs, removing the prior command failure. **High, confirmed:** their assertions remain narrower than the approved contracts: Property 9 has no Sites, targets, dates, foreign tenants, or reference-model comparison; Property 11 omits create-then-read equivalence; Property 12 generates only valid Sites; Property 13 has no activation state or Category/search filters; Property 34 generates no secret sentinel and does not test update/delete rejection, denial attribution, or cross-tenant visibility.

The local rerun produced 24 deterministic integration passes and 13 skips (12 PostgreSQL plus one Supabase). Expand the generated models and production adapter contracts before treating the green local command as checkpoint evidence.

## Closure decision and residual risk

**High, confirmed:** Tasks 7.1–7.16 cannot be closed as a completed group, and checkpoint 8 cannot be closed. Keep the service/audit foundation, configuration/Membership module, Publisher affiliation lifecycle, public query contract, analytics, property tasks, integration coverage, and E2E checkpoint open until these findings are fixed and provider-backed CI is green. Canonical Article/set-assignment and verified-claim behavior are substantially implemented, but their closure evidence remains coupled to incomplete Properties 11–13 and production contracts.

**Medium, confirmed residual risk:** the skipped provider contracts remain unobserved locally, and the current live Stage 3 test does not assert Membership listing or denial-audit insertion. CI must execute expanded contracts after the runtime-RLS fix.
