## Verified Auth crosses forced RLS without a tenant bootstrap exception

`app/cms/page.tsx` gets `identity.authUserId` from the server-only Supabase adapter’s `auth.getUser()` result and passes it to `resolveVerifiedUserOrganizations`; no request body, query parameter, local User ID, or Organization ID participates in discovery. The active-Organization cookie can only reorder an ID already discovered, and the switch and Stage 3 API routes independently require the verified local User’s active Membership and active Role before accepting a browser-supplied Organization ID.

The repository sets `app.auth_user_id` and `app.actor_id` transaction-locally, then calls `set_verified_user_context`, which verifies one active `users.id`/`auth_user_id` pair. `list_active_organizations_for_verified_user()` accepts no identity or tenant argument and joins only active Memberships, Organizations, and Roles for `current_verified_user_id()`. The settings expire with the transaction, preventing pool reuse from carrying identity context across requests.

The definer functions pin `search_path` to `pg_catalog, public, indicate_private`, qualify protected relations, run after public schema privileges were revoked, revoke execution from `PUBLIC`, and grant only `indicate_runtime`. Every production caller found sources the Auth UUID from `getUser()` or the verified-session adapter, and actor substitution fails the User-pair check. No privilege-escalation or request-level identity-injection path exists within the defined server-runtime trust model.

The live PostgreSQL contract seeds a second Organization and foreign User, expects actor discovery to return only Organization A, and expects no rows without verified context. The unit contract independently models two Users and projects only the verified identity’s Membership.

## `state_occurred_at` separates publication history from assignment maintenance

Migration `0005_stage3_discovery_outcome_timestamp.sql` adds the field as nullable, backfills published rows from `published_at` before `updated_at`/`created_at`, backfills other states from `updated_at`/`created_at`, then applies `DEFAULT now()` and `NOT NULL`. The Drizzle schema mirrors the non-null default and adds an Organization/Site/state/date index.

The `BEFORE UPDATE OF state, state_occurred_at` trigger restores `OLD.state_occurred_at` when state is unchanged, blocking explicit timestamp edits and assignment-only drift. On a state change it uses `statement_timestamp()` when the writer retained the old value, or preserves a distinct event time supplied by the transition writer.

`DrizzleStage3Repository` loads the field and includes it in Article-Site inserts and conflict updates. Because the upsert names both guarded columns, same-state full-state writes retain the database timestamp, while future modeled state transitions can persist a new transition time. `buildAnalytics` filters outcomes exclusively by `stateOccurredAt`.

Property 9 independently varies outcome time and later non-state edit time. The deterministic integration reassigns a published relation without moving its historical aggregate, and the live PostgreSQL contract changes only `active`, `version`, and `updated_at`, then verifies the September transition time survives the October edit.

Job analytics resolves Site/Region through `publishing_job_targets.article_site_id`, while public policy requires an active/activated Site, active Article and Region, and an active published assignment.

Repositories set Organization context and retain explicit Organization predicates; composite foreign keys and unique constraints enforce tenant coherence. Successful sensitive mutations and redacted audits share one transaction; runtime audit mutation is revoked and the append-only trigger rejects UPDATE/DELETE.

Canonical assignment deduplicates Sites and rejects invalid targets before persistence without copying Article content. Server-only Supabase/database modules and the client-secret scan preserve secret boundaries. Topology contracts still enforce one Next application, Vercel project, Supabase project/database/Auth instance, R2 bucket, Upstash resource, and public template.
