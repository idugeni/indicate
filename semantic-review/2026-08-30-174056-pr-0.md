# Stage 3 tenant CMS hardening and lifecycle expansion

Stage 3 closes the prior cross-tenant profile write, silent Role-grant loss, denial-envelope mismatch, denial-audit attribution, inactive-Region publication, and cross-assignment filtering defects. Most required lifecycle/filter controls are now present, backed by tenant-serialized mutation and audit persistence. Several CMS/security contracts remain incomplete, and the mandatory property command fails three tests. **Watch for:** **confirmed** module managers remain blocked without `site.read`; **confirmed** official claims cannot be revoked; **confirmed** Site Settings saves erase unrepresented settings; **confirmed** the Stage 3 checkpoint is red.

**Verdict**: NEEDS_CHANGES

## High-level view

Six prior blockers are resolved: Membership changes preserve `users.display_name`, Role grants are fully validated, resource/authorization denials share the 404 envelope, attributable denial auditing covers the CMS Membership boundary and supported actor identities, inactive Regions withdraw public content, and combined Site/state filters match one assignment. **confirmed:** the configuration fix now requires `site.read` before any authorized subprojection can load.

The Publisher and editorial surfaces now support editing, verification decisions, Article updates, assignment, and filters. **confirmed:** `article.read` returns full Publisher contacts/evidence without `publisher.read`, while Official Affiliations remain creation-only and cannot be changed or deactivated.

The CMS adds Region, Site, Role, Membership, Category, Author, Article, filter, and dashboard job-state controls. **confirmed:** Site Settings updates replace hidden branding/SEO/navigation values with empty values, and analytics lacks required Site/Region job and outcome dimensions.

Typed service errors preserve 400/409/503/500 while resource denials map to 404. **confirmed:** malformed GET filters and incomplete Publisher decisions still take the denial path instead of returning field-specific input errors.

**confirmed:** `npm run test:property` fails Properties 11, 13, and 34, so Task 8 cannot pass. Live PostgreSQL coverage remains Domain-only and the Stage 3 Playwright suite remains four flows.

<details><summary>Details</summary>

## Module projections still depend on Site access

`listConfiguration` separately reads Domain, Region, Site management, Role, and Membership projections, preventing the prior `site.read` overexposure. It nevertheless starts with unconditional `site.read` and derives organization/Site data from it (`tenant-business-service.ts:135-149`). **confirmed:** an actor holding only `domain.manage`, `region.manage`, `site.manage`, `role.manage`, or `membership.manage` is denied before their authorized projection is attempted. Remove the baseline permission or split the endpoint by module.

## Article lookup bypasses Publisher read boundaries

The editorial query authorizes only `article.read` and returns full Publisher objects alongside editorial references (`tenant-business-service.ts:364-369`). Those objects include contacts, evidence, verifier identity, and timestamps, while the Publisher module requires `publisher.read`. **confirmed:** Article readers can retrieve private Publisher-registry metadata through the editorial endpoint. Return reduced `{id, name, attributionLabel}` lookup values or authorize the Publisher projection independently.

## Official claims have no revocation path

The service creates an active Official Affiliation, and the route/CMS expose only `affiliation.create` (`tenant-business-service.ts:318-324`, `app/api/cms/stage3/route.ts:101`). **confirmed:** an operator cannot change scope/evidence or deactivate a claim even though public selection honors the `active` flag. Add versioned update/deactivate behavior under verifier permission with atomic before/after audits.

## Site Settings edits erase hidden configuration

`saveSiteSettings` replaces colors, social links, SEO, and navigation. The CMS exposes only name/description but always submits empty values for every hidden field (`cms-workspace.tsx:161`). **confirmed:** a basic text edit deletes persisted branding, social, SEO, and navigation configuration. Preserve omitted values or submit a prepopulated complete record.

## Analytics remains narrower than the Stage 3 contract

`buildAnalytics` groups Articles by Region, Site, Category, and Publisher, but jobs only by state and outcomes only by Site/state (`policies.ts:93-100`, `models.ts:216-223`). **confirmed:** Requirement 7.25’s Site/Region job dimensions and Region outcome dimension cannot be returned. Add those projections using the corresponding date-filtered job/outcome events.

## Invalid input still takes the denial path

The route maps typed `INVALID_INPUT` to 400 but returns query-schema failure directly as 404 (`app/api/cms/stage3/route.ts:36-38,73`). Publisher submit/approve without evidence and reject without a reason throw `Stage3AccessDeniedError` after parsing (`tenant-business-service.ts:296-301`). **confirmed:** malformed filters and incomplete verification forms receive no field-specific correction details. Use decision-specific schemas and the shared invalid-input envelope.

## Checkpoint evidence remains incomplete

A direct `npm run test:property` run failed three of eleven files. Property 11 spreads server-owned fields into a strict update DTO (`canonical-article-round-trip.property.test.ts:21`), and Property 34 generates labels ending in `-` (`immutable-atomic-auditing.property.test.ts:14-18`). **confirmed:** Property 13 also fails because its fixture creates no active Region (`published-site-content-selection.property.test.ts:16-20`) after the policy correctly began requiring one.

The live PostgreSQL suite has one Stage 3 case limited to Domain create/update, stale conflict, and audit insertion (`stage2-postgres-live.integration.test.ts:401-421`); the Stage 3 Playwright suite has four cases (`stage3-cms-critical-flow.spec.ts:9-47`). **confirmed:** repaired Role/Membership persistence, actor-specific denial auditing, Publisher/affiliation behavior, Article rollback, filter combinations, date/empty states, corrected resubmission, and new lifecycle controls are not exercised through production or browser contracts.
