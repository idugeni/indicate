# Durable media and multi-site publication runtime for Major Stage 4

This change adds private-object media reservation/completion, tenant/public media authorization, canonical publication fingerprints, durable publication jobs, Redis dispatch, fenced workers, reconciliation, CMS entry points, and the Stage 4 test matrix. PostgreSQL is the durable authority; tenant predicates, RLS, composite foreign keys, exact object keys, and typed denials form the intended security boundary. The implementation is not ready for checkpoint 10 because production-only paths diverge from the passing in-memory suite. **Watch for:** **high, confirmed** real R2 uploads fail checksum verification; **high, confirmed** completed job results depend on mutable Article Site rows; **high, confirmed** expired workers can still write and lease recovery can retry forever; **high, confirmed** exhausted dispatch produces an unreadable failed job.

**Verdict**: NEEDS_CHANGES

## High-level view

The media flow reserves a globally unique, owner-prefixed key before issuing one exact-key PUT authorization. **High, confirmed:** the browser declares a SHA-256 checksum, but the presigned PUT neither signs nor sends it, while completion compares provider metadata against that digest; real CMS uploads are rejected even though the fake provider accepts them.

Publication acceptance canonicalizes options and target sets, then uses `(organization_id, idempotency_key)` plus the fingerprint as the concurrency authority. **High, confirmed:** per-job targets do not persist their URL/timestamp outcome, so a later publication can erase or replace an earlier result. **High, confirmed:** acceptance also resets terminal Article Site state directly to `queued`, outside the declared transition relation. **High, confirmed:** terminal dispatch failure leaves targets queued, so reading the failed job throws instead of returning a Publication Result.

The worker uses Redis claims followed by a PostgreSQL lease and fencing token. **High, confirmed:** transition/release predicates do not require an unexpired lease, and expired-lease recovery ignores `maxAttempts`. **Medium, confirmed:** `batchSize` limits each fetch rather than the complete run.

Reconciliation repairs dispatch gaps, expired leases, and cleanup tasks. **High, confirmed:** transition-receipt/incomplete-acknowledgement recovery is absent. **Medium, confirmed:** discovery does not atomically claim rows, and production cleanup failures remain pending forever after retry exhaustion.

Public media authorization requires the resolved tenant/Site plus a Site Settings reference or published Article Site relation. **High, confirmed:** the Article branch does not verify that the owning Article remains active. **Medium, confirmed:** media archive creates no invalidation work for Site Settings or published-Article references.

Most Stage 4 reads use the standard 404-shaped tenant denial. **Medium, confirmed:** production media archive maps missing/cross-tenant rows to 409 while permission denials map to 404. **Medium, confirmed:** Stage 4 authorization denials are returned without the required security audit.

The local Stage 4 gate passed typecheck, lint, unit/property/in-memory integration, build, and Playwright. **Medium, confirmed:** R2 and Upstash contracts are skipped by the checked-in workflow, the R2 test performs no object round trip or anonymous-public denial, and test doubles differ from production. **Medium, confirmed:** the reservation owner-prefix constraint exists only in raw SQL, not the Drizzle schema definition.

<details><summary>Details</summary>

## R2 checksum authorization breaks the CMS upload contract

**High, confirmed.** The CMS sends a base64 SHA-256 digest in `media.reserve`, then uploads with only `content-type` (`app/cms/cms-workspace.tsx:183-188`). The R2 adapter signs only bucket, key, and content type, while HEAD maps `ChecksumSHA256` or falls back to ETag (`src/infrastructure/storage/r2-object-storage.ts:44-56`). Completion requires equality with the reserved browser digest (`src/application/stage4/media-service.ts:82-90`). ETag is not that digest, and the PUT did not request SHA-256 persistence, so normal uploads reach `uploaded_metadata_mismatch` and are deleted.

Pass the declared checksum through the storage port, sign `ChecksumSHA256`, send the required upload header, and compare the provider’s SHA-256 field. Cover signed PUT, HEAD, completion, GET, delete, and anonymous denial against a real or faithful provider.

## Publication history aliases mutable Article Site outcomes

**High, confirmed.** `publishing_job_targets` stores no published URL/timestamp (`src/infrastructure/db/schema/operations.ts:60-72`). Status joins each target to the current `article_sites` outcome (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:182,211`), while a later acceptance clears that relation (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:156-159`). An old published job can report zero URLs and later report the newer job’s URL.

Persist terminal URL/timestamp/outcome on the immutable target and derive historical status exclusively from target snapshots. Add a PostgreSQL republish test proving job A remains unchanged after job B uses the same Article/Site.

**High, confirmed.** Acceptance also performs `published|failed -> queued` directly on `article_sites`, while migration guards cover only jobs and job targets (`drizzle/0006_stage4_media_publication_runtime.sql:27-57`). Define the republish/current-projection model and enforce the required Article Site transition relation in PostgreSQL instead of allowing state rewinds.

## Failed dispatch cannot produce its required result

**High, confirmed.** Exhausted dispatch marks only the job `failed`; targets remain `queued` (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:180`). Failed-job status calls `projectPublicationResult`, which throws unless target states are terminal (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:182`; `src/domain/stage4/publication-policy.ts:93-97`). CMS/API therefore cannot retrieve the required final state, success count, and URLs.

Make dispatch-terminal failure a coherent durable result and add service/live-PostgreSQL coverage for first-attempt terminal failure and retry exhaustion.

## Lease expiry does not revoke worker ownership

**High, confirmed.** `runnableTargets` checks lease time, but `transitionTarget` and `releaseJob` check only fencing token and owner (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:187-189`). A publisher call can cross the deadline and still commit until reconciliation changes ownership. Existing tests recover and re-claim before the stale write, missing this interval.

Require an unexpired database-time lease on every fenced write/release or renew before bounded external work. Test expiry without reconciliation.

**High, confirmed.** Recovery always moves processing targets/jobs to `retrying` without checking attempts or retry policy (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:191-204`). Repeated timeout cycles can exceed `maxAttempts`; recovery must fail exhausted targets and aggregate the job.

**Medium, confirmed.** The worker repeatedly fetches another `batchSize` targets until its deadline (`src/application/stage4/publication-worker.ts:32-75`). Track one per-run target budget and test a job larger than two batches.

## Reconciliation omits recovery records and exclusive claims

**High, confirmed.** `publication_transition_receipts` exists, but no Stage 4 code inserts, acknowledges, scans, or reconciles it. Reconciliation handles only leases, dispatch gaps, and cleanup (`src/application/stage4/publication-worker.ts:86-99`), leaving Task 9.6 and Requirement 12.48 incomplete. Implement receipt-backed commit/acknowledgement recovery with crash-point tests.

**Medium, confirmed.** Discovery functions perform bounded SELECTs without claiming rows or using the designed `FOR UPDATE SKIP LOCKED` (`drizzle/0006_stage4_media_publication_runtime.sql:66-99`). Overlapping reconcilers can increment dispatch attempts more than once and duplicate cleanup calls. Add atomic claims or state/version compare-and-set updates.

**Medium, confirmed.** Cleanup uses a fallback delay after policy exhaustion, and production always rewrites `status='pending'` (`src/application/stage4/publication-worker.ts:96-98`; `src/infrastructure/db/repositories/drizzle-stage4-repository.ts:207-209`). The fake instead fails after five attempts (`src/infrastructure/testing/stage4-memory.ts:303-305`). Persist a cleanup bound and transition exhausted tasks to `failed`.

## Public media authorization omits revocation edges

**High, confirmed.** Article media checks active media, active Site, and a published Article Site relation, but never loads the Article’s active/archive state (`src/domain/stage4/media-authorization.ts:8-22`; `src/infrastructure/db/repositories/drizzle-stage4-repository.ts:127-138`). An archived Article can continue receiving signed media URLs. Require the exact same-Organization Article to remain public-eligible and test archived Articles.

**Medium, confirmed.** Production `archiveMedia` changes state and audits but inserts no invalidation task (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:116`). Existing signed URLs/cache entries remain live until expiry. The fake invalidates only Site Settings references and misses published Article references (`src/infrastructure/testing/stage4-memory.ts:151-158`). Derive all affected Sites and persist deduplicated invalidation intents atomically with archive/audit.

## Denial behavior and security auditing diverge

**Medium, confirmed.** Production `archiveMedia` maps every zero-row optimistic update—including absent and cross-Organization/RLS-hidden rows—to conflict, while the route returns 409 for conflict and 404 for `RESOURCE_UNAVAILABLE` (`src/infrastructure/db/repositories/drizzle-stage4-repository.ts:116`; `app/api/cms/stage4/route.ts:45`). Resolve same-tenant existence first and reserve 409 for a verified stale version.

**Medium, confirmed.** Stage 4 services return non-disclosing envelopes for `Stage4AccessDeniedError` but append no denial audit (`src/application/stage4/media-service.ts:35-73`; `src/application/stage4/publication-service.ts:44-58`). Add a sanitized requesting-tenant security event without the foreign target identifier, preserving the external 404 shape.

## Provider and schema evidence does not support checkpoint 10

**Medium, confirmed.** The workflow supplies no R2/Upstash credentials while provider suites use `describe.skipIf`; the local gate skipped both (`.github/workflows/stage2-quality-gate.yml:21-30`; `tests/integration/stage4-provider-live.integration.test.ts:9-25`). The R2 case checks only bucket HEAD and signature shape despite claiming private-bucket behavior. Make representative provider contracts mandatory or use faithful local emulation covering object/checksum and Redis lease/duplicate-claim behavior.

**Medium, confirmed.** Migration 0006 adds `media_key_reservation_owner_prefix`, but the Drizzle table declaration contains only owner-count and size checks (`src/infrastructure/db/schema/editorial.ts:246-250`). Add the named check to the Drizzle schema and assert schema/migration parity.
