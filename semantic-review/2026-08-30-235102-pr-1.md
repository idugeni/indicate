# Fail-closed Stage 6 platform authorization and PostgreSQL timestamp normalization

The correction closes the SQL `NULL` authorization hole by making the platform-permission predicate return explicit `false` whenever verified actor context is absent or incomplete. It also normalizes both `Date` objects and raw postgres.js `timestamptz` strings before Stage 6 projections cross the repository boundary. A forward migration advances the required schema from 11 to 12 and is wired into discovery and fresh-database bootstrap. The four failures reported by CI run 33342438835 are addressed by the changed behavior and targeted assertions. **Watch for: confirmed validation limitation — the fresh PostgreSQL 17 runtime suite could not be rerun in this sandbox because the host cannot reach a container-published loopback port; no blocking code concern was found.**

**Verdict**: APPROVED

## High-level view

Platform customer administration now requires an owner-provisioned platform grant, a transaction actor matching the requested actor, and a verified active user matching that actor. `COALESCE(..., false)` converts missing SQL context from `NULL` to denial without weakening the owner-only provisioning or tenant-role boundaries.

Stage 6 repository projections now accept the two timestamp representations produced at runtime: Drizzle-declared `Date` values and raw strings returned by postgres.js. The normalizer validates calendar and offset fields, converts offsets to UTC, and truncates PostgreSQL microseconds to JavaScript millisecond precision.

Migration 0011 replaces only the affected permission function, records schema version 12, and is registered in the journal, migration policy, schema gate, fresh bootstrap, and live-suite precondition. Version 11 deployments remain blocked until the correction is applied.

## Platform grants require verified transaction context

The previous predicate could evaluate to `NULL` when `app.actor_id` and verified-user context were absent. In PL/pgSQL, `IF NOT NULL` did not enter the denial branch, so `stage6_list_customers` continued into its cross-tenant query; this is the first failure recorded in CI run 33342438835. Migration 0011 wraps the full predicate with `COALESCE(..., false)`, making absent context, inactive or mismatched actors, and missing grants deterministic denials.

`stage6_provision_platform_permission` remains revoked from `PUBLIC` and `indicate_runtime`, and the grant table remains inaccessible to the runtime role. Tenant roles cannot acquire platform permissions because the scope guard accepts only same-organization permission rows. The live contract checks absent-context `false`, the resulting `42501`, runtime provisioning and tenant-role escalation denial, mismatched verified-actor denial, and the owner-provisioned success path.

## One timestamp boundary covers all affected Stage 6 projections

CI's replay failure showed postgres.js returning `2026-08-30 23:41:14.157683+00`, while the repository called `toISOString()` as though every value were a `Date`. The same assumption affected API-key lookup and subscription/customer return paths, explaining the API authentication and subscription-update failures: repository mapping exceptions became unsuccessful service results.

`normalizeStage6Timestamp` accepts a valid `Date` or a PostgreSQL timestamp string with `Z`, hour-only offset, or hour-and-minute offset. It validates calendar and clock fields, converts the instant to UTC, and emits the domain's millisecond ISO format. Required and nullable timestamps now use it for API keys, replay claims, customers, subscriptions, Telegram mappings, and conversations. Unit coverage includes raw UTC and `+07:00` values plus malformed dates and types; the Stage 6 live contract covers replay, API-key, customer, and subscription workflows.

## Schema version 12 remains coherent across migration and activation

Migration 0011 is forward-only and inserts version 12 after version 11. Its journal tag, policy marker, fresh Stage 2 bootstrap entry, Stage 6 precondition, `REQUIRED_SCHEMA_VERSION`, and readiness unit test all advance together, with version 11 explicitly rejected.

## CI run 33342438835 failure closure

All four annotations map to changed behavior: absent-context platform listing now denies; replay claims normalize raw timestamps; API-key lookup normalizes creation, update, expiry, and last-use values before authentication; and subscription/customer projections normalize returned timestamps before service acknowledgement. No PR discussion or inline review comments raised additional concerns.
