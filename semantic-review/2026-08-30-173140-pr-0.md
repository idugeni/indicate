# Tenant-serialized Stage 3 CMS and editorial services

Major Stage 3 now serializes PostgreSQL writes per Organization, persists Role and Membership creation, preserves unchanged permission grants, invalidates changed Publisher verification, and guards late browser responses after organization switches. The editorial projection resolves Publisher attribution, supports multi-Site analytics and date ranges, and rejects foreign filter identifiers. **Confirmed:** authorization, public-selection, and CMS lifecycle gaps remain. **Watch for:** **confirmed** configuration reads expose Membership and Role data under `site.read`; **confirmed** Membership administration changes the global User profile across tenants; **confirmed** public content can survive Region deactivation.

**Verdict**: NEEDS_CHANGES

## High-level view

The Organization row lock makes tenant writes serial, so stale command versions are checked against current locked state. The prior lost-update, missing insert, and unrelated Role-grant rewrite findings are resolved, but **confirmed** Role updates can still report and audit permission names that PostgreSQL silently discards.

The repository scopes loaded records by Organization and the service ownership-resolves supplied editorial filter IDs. **Confirmed:** `listConfiguration` returns Roles and Memberships under only `site.read`, while Membership changes write the tenant-entered display name to the global `users` row.

Denial-audit write failures now become sanitized dependency failures. **Confirmed:** POST commands still distinguish context-level and service-level denials by HTTP status; route-level Membership failures bypass denial auditing; production denial auditing skips API Key, Telegram, and system actors.

Publisher identity changes now clear verification, and linked Articles receive registry-derived attribution. **Confirmed:** public selection ignores the Region’s current lifecycle status, and combined Site/publication-state filters can be satisfied by different assignments.

The CMS adds configuration, Publisher decision, Category, Author, Article lifecycle, and assignment controls with stale-response guards. **Confirmed:** required lifecycle and filter workflows remain absent, and the PostgreSQL/E2E matrix does not exercise the repaired security-sensitive families.

<details><summary>Details</summary>

## Configuration reads bypass module-specific RBAC

`listConfiguration` requests only `site.read` and then returns Domains, Regions, Sites, Site Settings, Roles, and Memberships (`tenant-business-service.ts:128-132`). **Confirmed:** a Site reader can enumerate member identities and authorization data without `membership.read`, `role.manage`, `domain.read`, or `region.read`. Split the projection into permission-specific queries, or redact each collection unless the transaction verifies its corresponding permission.

## Membership administration mutates a cross-tenant User profile

The Membership command accepts `displayName` as Organization-scoped state (`schemas.ts:27`, `tenant-business-service.ts:216-225`), but the production adapter updates `users.display_name` by User ID alone (`drizzle-stage3-repository.ts:136`). The in-memory adapter instead keeps that value in the tenant Membership snapshot. **Confirmed:** an administrator in one Organization can change the shared User name observed through every other Organization containing that User. Keep global profile changes outside Membership administration, or add an Organization-local Membership label and align both adapters.

## Role writes can report grants that PostgreSQL discarded

Role input permits any bounded permission string (`schemas.ts:25-26`). The adapter deletes existing grants, selects existing platform or same-Organization Permissions, and inserts only the matching subset without checking for unmatched names (`drizzle-stage3-repository.ts:122-125`). **Confirmed:** a misspelled permission returns success and appears in the audit but disappears on reload; an update can also remove valid grants while reporting a different result. Resolve the complete permission set before deleting grants and reject unavailable names.

## POST denials reveal which authorization stage failed

The POST route returns 404 when Organization context cannot be established but maps every service error—including non-disclosing authorization/resource denials—to 400 (`app/api/cms/stage3/route.ts:65-81`). **Confirmed:** callers can distinguish “no Membership for this Organization” from “Membership exists but permission or target is unavailable” despite the common envelope. Map typed denial, validation, conflict, dependency, and internal outcomes explicitly, preserving one status and shape for absent, foreign, and unauthorized resources.

## Denial audits stop at the CMS Membership boundary

The Stage 3 route exits before the service when Membership is missing or inactive (`app/api/cms/stage3/route.ts:35-41`), and Active Organization switching has the same early return. Production `recordDenied` also queries `memberships.user_id = actor.actorId` for every actor type and returns when none exists (`drizzle-stage3-repository.ts:82-87`). **Confirmed:** context-level User denials and all API Key, Telegram, or system denials can disappear from the security trail. Add an attribution-safe audit at the identity/Organization boundary and validate each actor type through its credential or mapping rather than a User Membership lookup.

## Region deactivation does not withdraw published content

`selectPublicArticles` requires an active Site and Article plus an active published Article Site relation (`policies.ts:43-51`), but never checks the Region record. **Confirmed:** deactivating or archiving a Region leaves regional content eligible, contrary to Requirement 10.11. Require an active Region whenever Site or Article selection has regional context; Property 13 currently creates no Region records and cannot detect this case.

## Site and publication-state filters match different assignments

The editorial policy checks that some active assignment matches `siteId`, then separately checks that some active assignment matches `publicationState` (`policies.ts:28-30`). **Confirmed:** an Article published on Site A and failed on Site B matches `{ siteId: A, publicationState: failed }`. Require one Article Site row to satisfy both dimensions and add generated multi-Site/multi-state cases.

## Browser workflows remain short of the Stage 3 lifecycle

**Confirmed:** the CMS still lacks Region/Site/Role update and deactivation, Membership creation/deactivation/removal, Publisher editing and Official Affiliation management, Category/Author updates, Article content updates, and combined editorial filters. The GET schema forwards only editorial `search` and no analytics or audit filters (`app/api/cms/stage3/route.ts:21,50,58-59`), so configured date and actor/action/target/outcome filters are unavailable. Dashboard rendering also drops `jobsByState` because it renders only top-level numbers (`cms-workspace.tsx:142-144`). Complete these browser and adapter contracts before closing tasks 7.2–7.8.

## Production contracts do not cover the repaired boundaries

The live PostgreSQL suite has one Stage 3 case covering Domain create/update, one stale version, and audit insertion (`stage2-postgres-live.integration.test.ts:401-421`). **Confirmed:** it does not exercise Role grant preservation, Role/Membership inserts, permission reconciliation, concurrent Organization locking, Membership profile scope, denial audits, Publisher re-verification, assignments, or rollback across security-sensitive families. The six in-memory Stage 3 integration cases and four Stage 3 E2E flows also omit corrected resubmission, required updates/deactivations, verification, combined filters, analytics empty/date behavior, and audit filtering.

The property command still reports the previously recorded Property 11 and Property 34 test-shape failures; they are not implementation regressions. They leave canonical round-trip and audit properties unexecuted beyond the first invalid sample, while Property 13 omits Region lifecycle and combined assignment filters. Repair those inputs and extend the generated models to cover the behavioral gaps above.
